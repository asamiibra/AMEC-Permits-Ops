# Page design contract

The canonical Proposal page hierarchy is:

1. Proposal Register: current business state, role lane, filters, owner, next action, activity.
2. New Proposal: source-first selection, explicit required fields, source-specific file capture, honest no-source path.
3. Proposal Workspace: identity header, five-stage lifecycle, main stage surface, attention rail, protected state, audit identity.

The five stages are Intake & Sources, Engineering Preparation, Commercial Review, Client Response, and Contract Handoff. Completed stages remain inspectable; future stages are visibly future. Desktop uses a main workspace plus attention rail, tablet collapses the rail below the workspace, and mobile uses cards, stacked forms, and horizontally scrollable stage navigation.

No raw UUID, raw JSON, backend enum, fixture identifier, or `Opportunity Ref` is primary Owner-facing content. Server truth is displayed through labels and explicit unavailable/not-recorded states.
