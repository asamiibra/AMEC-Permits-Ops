# Future Branching Policy

`main` is the canonical integrated product baseline. Use short-lived `feature/<scope>`, `fix/<scope>`, and `chore/<scope>` branches from current main; merge through the normal protected workflow; run candidate and production gates; then retire the branch. Do not create permanent module branches. Dashboard, Administration, Proposal, Contract, Permit, storage, Source Intake, and Vercel work share canonical models, migrations, resolvers, RBAC, audit, and evidence seams.
