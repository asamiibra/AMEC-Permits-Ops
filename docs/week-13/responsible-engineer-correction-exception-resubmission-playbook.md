# Responsible Engineer correction / exception / resubmission playbook

Review technical Findings, drawing metadata mismatches, authority/precheck design comments, and evidence requirements. Create a correction revision when the change is material; the old package, precheck, and closure history remain visible and stale where applicable. Re-run precheck, review the new package hash, and verify closure evidence using the configured verifier role.

Disputes and reopens use the existing Week 10 routes. A Responsible Engineer may make the technical/professional decision; System Admin, Process Champion, and model output may not substitute for it. PermitOps surfaces evidence/control state only. Resubmission readiness remains blocked until current revision, package, precheck, dependencies, portal reconciliation, and Findings all pass.
