# Client Document and LPO

Client Document and LPO writes create canonical Document/DocumentVersion records plus Contract evidence pointers; versions are append-only and downloadable through an authorized route. Read-back exposes version, status, provenance, and source role. Unauthorized access and unsupported/failure paths are represented as errors rather than fake success.

LPO received is separate from Contract acceptance, Project Activation, and Invoice authorization. Required/optional/conditional/not-applicable behavior is a policy seam. Final LPO requiredness and official document content remain Owner Input Required where not configured.
