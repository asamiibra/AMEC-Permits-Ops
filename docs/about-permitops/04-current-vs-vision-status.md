# Current implementation versus broader vision

## Current permit core

The current permit core is a controlled permit-integrity workflow:

`Source information → observations/evidence → reconciliation → verified facts → controlled forms/Excel/package/Municipality preparation → human review → authority precheck/feedback → correction/revision → human final submission → official review/findings/history`

The UI can open the permit portfolio and workspace, show deterministic next action, inspect evidence/conflicts/readiness, prepare synthetic Municipality state, record read-back/precheck/findings, and keep history/lineage/staleness evidence. It never claims that the synthetic simulator is a live authority connection.

## Expansion runtime already implemented

The repository contains bounded synthetic foundation/runtime for opportunities, RFQ/tender, quotation, contract, checklist, shared evidence, communication drafts, assistant handoffs, and unified queues. These are shown with prototype/foundation labels because runtime structures and bounded demonstrations do not prove complete owner-approved business workflows.

## Foundation only

The expansion models, template/rendering primitives, communication draft state, engineering/finance/handover structures, and shared assistant context are foundation when the end-to-end business workflow, authorization, or external integration is absent.

## Planned / pending scope

Live authority writes, production monitoring authorization, automatic external sends, machine final submission, payment, signing, certification, automatic accounting posting, autonomous professional/commercial approval, and complete quotation/contract/invoice/handover release remain outside the current environment.

## Safety boundary

The repository README states synthetic-only data, no real credentials/OTPs, no production Municipality URL, no machine final submission, no payment/signing/certification, and no real external-system route. The formal G10 evidence says `G10_NOT_RUN`; zero-tolerance safety counters are zero for the repository run, not a production authorization.
