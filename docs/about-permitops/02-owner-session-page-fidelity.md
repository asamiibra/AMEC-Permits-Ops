# Owner-session page fidelity

The explainer preserves the owner-session story while separating current permit runtime from the broader AMEC vision.

| Owner-session topic | Classification | How the page represents it |
|---|---|---|
| RFQ / tender / client inquiry | BROADER_VISION_FOUNDATION | Broader workflow card; not counted as permit MVP |
| AMEC quotation | BROADER_VISION_FOUNDATION | Status-aware broader workflow; human commercial authority remains explicit |
| Commercial human authority | SAFETY_BOUNDARY | AI may prepare information; it cannot authorize binding terms or release |
| Client acceptance | BROADER_VISION_FOUNDATION | Not presented as a complete workflow |
| Contract and supporting attachments | BROADER_VISION_FOUNDATION | Foundation only; no claim of contract execution |
| Checklist / missing / expired | BROADER_VISION_FOUNDATION + permit validity | Permit validity is prototype-backed; broader checklist remains foundation |
| Reference number / project status Excel | CURRENT_IMPLEMENTED_PROTOTYPE | Controlled project/Excel projection evidence; human-owned areas remain protected |
| Server / Synology | CURRENT_IMPLEMENTED_PROTOTYPE | Controlled source linkage, synthetic adapter |
| Administrative document comments | BROADER_VISION_FOUNDATION | Kept distinct from engineering and authority comments in the story |
| Engineering review concept / Authorized Engineer | SAFETY_BOUNDARY + BROADER_VISION_PLANNED | Human role card; no autonomous professional approval claim |
| Permit core | CURRENT_IMPLEMENTED_PROTOTYPE | Full 8-stage explainer and runtime links |
| Municipality preparation | CURRENT_IMPLEMENTED_PROTOTYPE | Assisted/synthetic preparation, reconciliation, read-back |
| Authority AI precheck | CURRENT_IMPLEMENTED_PROTOTYPE | Synthetic capture and correction loop; not approval |
| Human submission | SAFETY_BOUNDARY | Final action remains with authorized human |
| Status / comments / correction / resubmission | CURRENT_IMPLEMENTED_PROTOTYPE | Findings, revisions, gates, monitoring, history |
| Invoice / finance | BROADER_VISION_FOUNDATION | No automatic accounting posting or invoice release claim |
| Communication | BROADER_VISION_FOUNDATION | Draft/runtime structures do not imply automatic send |
| Handover | BROADER_VISION_FOUNDATION | No complete handover release workflow claim |
| Four assistants | CURRENT_IMPLEMENTED_PROTOTYPE | Shared queue/handoff prototype with human-send policy |

Owner details such as quotation process, reference communication, project-status Excel, contract attachment linkage, handover communication, missing/expired checklist, administrative comments, project status, approval-check communication, and the input → AMEC Form → follow-up → output pattern remain visible as context or are classified as foundation/planned where runtime evidence is incomplete.
